## Локальный запуск только для тестов

```bash
npm --prefix web ci --ignore-scripts
npm --prefix web run build
go run ./cmd/evolving-preview
```

Адрес: `http://127.0.0.1:8766/evolving/`. Это адрес на VDS, не на компьютере пользователя. Процесс останавливается Ctrl+C; не оставлять его работать после проверки. Параметр `-listen` меняет адрес, по умолчанию сервер слушает только loopback. Для пользовательской пробы использовать HTTPS-стенд выше.

Без `PREVIEW_DATABASE_URL` сохраняется прежний режим без базы. Для сохраняемой пробы нужен отдельный PostgreSQL с базой **и ролью** `opencraft_preview`. Другие имена отвергаются до подключения. Разрешены loopback или точный явно заданный `PREVIEW_DATABASE_HOST` с суффиксом `.railway.internal`; проверяются и fallback-адреса. `DATABASE_URL` никогда не используется как запасной вариант. Используется уже установленный pgx, не новый тип хранилища.

На текущем VDS создан контейнер `opencraft-evolving-preview-db`, том `opencraft-evolving-preview-data`, порт `127.0.0.1:55432`. PostgreSQL 17; использованный digest образа: `sha256:67f41722b7a8cbdb868a44a4995c846eddfdc2973bccb291ce937dce88ad5675`. Случайный пароль и DSN находятся в игнорируемом `.env.preview.local` с правами 0600. Рабочая база не открывалась. В локальной базе остаются проверочные гости и сообщения.

Запуск сохраняемой пробы на этом VDS:

```bash
sudo docker start opencraft-evolving-preview-db
set -a
. ./.env.preview.local
set +a
npm --prefix web run build
go run ./cmd/evolving-preview -listen 127.0.0.1:8767
```

Адрес проверочной версии — `http://127.0.0.1:8767/evolving/`. SSH-туннель для пользовательской пробы больше не нужен: используется опубликованный стенд.

Для новой машины: создай приватный `.env.preview.local` по переменной из `.env.example`, добавь `POSTGRES_USER=opencraft_preview`, `POSTGRES_DB=opencraft_preview`, `POSTGRES_PASSWORD` со случайным паролем, совпадающим с DSN. Затем запусти `docker run -d --name opencraft-evolving-preview-db --env-file .env.preview.local -p 127.0.0.1:55432:5432 -v opencraft-evolving-preview-data:/var/lib/postgresql/data postgres:17` и команды запуска выше. Изменение env-файла не меняет пароль уже инициализированной базы.

Остановка контейнера `sudo docker stop opencraft-evolving-preview-db` сохраняет том. Том не удалять для «перезапуска»: в нём история. Резервное копирование и восстановление ещё не отрепетированы; наличие тома не заменяет бэкап.

Реализованы пять устройств тела: длинноногая фигура, широкая шестиногая, парящий многогранник, отдельные фрагменты и асимметричное тело. Геометрия и материалы переиспользуются, новых библиотек нет. Старый рецепт `shape-` сохранён; новый — `shape2-`. Профиль хранит `avatarVersion` и `appearanceChoicePending`. Новые гости получают версию 2 и закрытый выбор. Старым доступно одно решение перед входом: оставить прежний облик или выбрать новый. Возврат к предыдущему варианту не расходует это решение.

`POST /evolving-api/appearance` принимает `{keep:true}` либо `{seed:number}` с гостевой cookie и проверкой Origin. Облик и закрытие права записываются одним условным UPDATE; повтор после завершения даёт 409, клиент перечитывает профиль. Во время активного подключения смена запрещена. Дополнительные колонки не удаляют данные; их старые defaults защищают входы, завершаемые прежним сервером во время переключения. Новый код явно записывает версию 2 и закрытое право.

API версии 2: создание сессии требует `avatarVersion:2`; соединение — `/ws?recipes=2`. Старый клиент без версии не допускается к новым формам. Для отката нужна сборка, понимающая оба рецепта и сохраняющая закрытые права. Возврат к старому бинарнику версии 1 после появления новых обликов небезопасен: он интерпретирует их иначе. Колонки не удалять, seed не пересчитывать.

Чат: кнопка с точкой новых сообщений, компактное окно справа, добровольная развёрнутая история. На узком экране окно над стиком, сцена занимает свободное место сверху; камера приближается при уменьшении сцены. Открытие не вызывает клавиатуру. Ввод, фокус списка для клавиатурного чтения и развёрнутая история останавливают движение. Черновик и место чтения сохраняются при изменении окна; приход сообщений не вытесняет читаемую страницу.

Проверки: `go test ./...`, `go vet ./...`, race-проверка server/world/store, 42 клиентских теста, сохраняемый и временный сетевые сценарии. `check-evolving-persistence.mjs` также запускает `TestPreviewAppearance` на отдельной локальной базе: конкурентный выбор, сохранение старого тела, legacy-вставка и повтор миграции. `node web/tools/check-evolving-ui.mjs` проверяет временный сервер на 8767 через agent-browser: пять форм, вход, постоянство профиля, ширины 320/390/1280, фокус, черновик и прокрутку. ## Что работает

- Общая чёрная 3D-сцена, процедурные персонажи, умеренная перспектива и мягкое следование камеры.
- Вход с именем и выбор облика до создания гостя. Возвращаются сохранённые имя, seed и версия рецепта; совпадение имён не даёт доступ к чужому персонажу. Разовое обновление старого гостя описано выше.
- Стрелки/WASD и виртуальный стик; показ присутствующих игроков и их движения.
- В сохраняемом режиме — история с датами, страницы по 100 сообщений, «Раньше» в развёрнутом окне и «К свежим». Новые сообщения дочитываются по курсору примерно раз в секунду; в DOM остаётся не более 200 строк. Компактный разговор не скрывает стик и не фокусирует ввод.
- Подтверждение отправки — только после commit. Повтор с тем же ID от того же гостя возвращает прежнюю запись; другой текст с этим ID отвергается. Черновик и ID неподтверждённой отправки сохраняются в localStorage, если браузер разрешает запись. Автоматической повторной отправки нет.
- Состояния загрузки, недоступного сервера, разрыва соединения и потери графического контекста. После потери графики предлагается перезагрузка.

## Границы среза

Гостевой доступ — случайный 256-битный токен в HttpOnly/SameSite=Strict cookie на 30 дней; в базе только его SHA-256. Secure включается при прямом HTTPS или явно настроенном HTTPS-стенде. Это не полный аккаунт: нет переноса между устройствами, восстановления после потери cookie, свободной смены имени/облика и продления доступа. Единственное исключение для облика — разовый переход старого гостя, описанный выше. Одна активная WebSocket-сессия на гостя в одном процессе; другая вкладка получает отказ, а не перехватывает управление. Cookie не различает порты одного hostname: локальные приложения должны быть доверенными.

Позиция записывается при отключении и штатной остановке сервера. Принудительное завершение процесса или недоступная база могут потерять перемещение после последнего сохранения. Имя, облик и уже подтверждённые сообщения записываются сразу. Ошибка базы не останавливает движение уже подключённых игроков, но блокирует восстановление гостя и подтверждение нового сообщения.

Нет артефактов, звука, агента эволюции, автоматического выпуска и полноценной защиты публичного сервиса. Беседа доступна всем гостям и оператору пробы; автоматического удаления нет — это указано в раскрываемом «Об игре» до входа. Перед приглашением реальных участников ещё нужны политика хранения/удаления, резервное восстановление и проверка настоящих телефонов.

В режиме **без базы** всё ещё используется эфемерный бинарный чат без ID сообщений. Только 200 строк текущего посещения, повтор может дублироваться, черновик не переживает перезагрузку. Его интерфейс прямо сообщает, что история не сохраняется.

Three.js `0.185.1` закреплена в `web/package.json` и lockfile. Браузеру отдаются только её локальные `three.module.js` и `three.core.js`; внешний генератор графики и CDN не требуются. `@types/three` — сборочная зависимость, её вспомогательные пакеты не подключаются в сцену. Компиляция использует существующий `tsc`; новые `.js` рядом с `.ts` игнорируются Git.

У sim нет доступа к рабочей базе; DB-запросы выполняются вне тика. `JoinPreview` принимает уже проверенный профиль и позицию; Hello не может подменить имя/seed гостя. Бинарный `CChat` в сохраняемой версии игнорируется: сообщение идёт через HTTP-запись. Обычный `NewSim`/`server.New` и production entrypoint сохраняют прежнее поведение.

До соединения клиент проверяет `/preview-info` (`mode=evolving-preview`, `persistent`, `apiVersion=1`). Только сохраняемый режим открывает `/evolving-api/session` (GET/POST) и `/evolving-api/messages` (GET/POST). Cookie обязательна для чтения истории и подключения; POST также требует JSON и точного Origin. Лимиты: тело 4096 байт, имя 24 символа, сообщение 200, новый текст не чаще одного за 500 мс от гостя. Общий лимит регистрации/запросов ещё не реализован.

ID сообщения передаётся строкой, сортируется **числом**, cursor `after`/`before` исключительный. Короткий общий advisory lock перед INSERT обеспечивает порядок commit: нельзя пропустить поздний commit с меньшим ID. История не зависит от теряющего кадры канала движения. Один процесс; за HTTPS-proxy требуется точный `PREVIEW_PUBLIC_ORIGIN`. Старый `ALLOWED_ORIGINS` также действует, если задан.

Создание первоначальной схемы идемпотентно, но `CREATE IF NOT EXISTS` не мигрирует изменения таблиц. Следующее изменение схемы требует явной совместимой миграции. Откат к версии без базы не удаляет схему, однако перестаёт показывать сохранённый разговор; это не полноценная репетиция восстановления.
