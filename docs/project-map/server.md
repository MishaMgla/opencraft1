# server (Go engine)

the authoritative real-time engine. one process, one binary.

## packages
- `cmd/server/main.go` — entrypoint. starts the sim goroutine and the http server (listens on `:$PORT`, default `8080`), graceful shutdown on SIGINT/SIGTERM. builds the `/version` payload from ldflags, Go VCS metadata, or local binary timestamp fallback.
- `internal/wire` — binary protocol. encoders (server→client) + `ParseClient` decoder (client→server). little-endian, int16 positions. Carries player snapshots, role + character choice on `CHello`, shared paint (`CPaint`/`SPaint`), ult activation (`CUlt`), roster/ult state including character (`SPlayer`), one-shot avatar shake (`SShake`), one-shot cosmetic jump (`CJump`/`SJump`), and one-shot tile ignition (`SFire`), and bomb placement/detonation (`CBomb`/`SBomb`/`SBlast`) messages. **single source of truth for the wire format; `web/src/wire.js` must mirror it byte-for-byte.**
- `internal/world/grid.go` — uniform 32×32 spatial grid (cell 256) over the 8192×8192 playable world. `Neighbors` returns the 3×3 area-of-interest helper retained for spatial queries.
- `internal/world/sim.go` — the only goroutine that touches world state. 15 Hz tick. owns players, their fixed connected-session role, selected character, ult charge/trail state, and the painted-tile map. drives join/input/paint/ult/jump/leave/ping via a command channel, emits full-current-map snapshots to every client, sends enter on join and leave on disconnect, broadcasts roster state on join/charge/ult changes, broadcasts jump events on fresh `Space` presses, and broadcasts shake events when a player enters someone else's painted tile. owns the fixed **3×3 permanent temple** northeast of spawn: its southwest tile is `(2048,1792)`, leaving `(2048,1920)` clear between it and spawn; movement segments cannot enter or cross its nine tiles, saved positions inside it fall back to spawn, persisted paints on its footprint are ignored, paint/fire/bomb placement cannot affect it, and blast arms stop before its edge. runs a **fire cellular automaton** over the painted map: painting lava ignites flammable (grass/flowers) neighbours and painting flammable next to lava/fire self-ignites; a fire step every `fireTickEvery` (8) ticks spreads each burning tile one ring to flammable neighbours, and after `burnTicks` (3) steps a burning tile becomes temporary **ash** (`0x3A4757`, broadcast as a normal `SPaint`) for about 1 second before the server broadcasts a color-0 `SPaint` clear and removes it from the painted map. The transient `burning` and ash-timer sets are sim-goroutine-owned like `painted` and are **never persisted** — `SFire` ignite frames, ash `SPaint`, and clear `SPaint` frames cross the wire, so a new joiner may miss an in-progress burn but never receives expired ash as durable terrain. runs a **bomb layer** (Bomberman Increment 1): `CBomb` drops a fused bomb on the actor's tile (`bombFuseTicks`≈38, max `maxBombsPerPlayer` live, one per tile, broadcast `SBomb`); each tick decrements fuses and detonates any at 0 — a `+` blast of `bombRange` (2) tiles per arm (clipped at the world edge or temple) that ignites flammable tiles and destroys other painted tiles to ash, chaining any bomb caught in a blast (`detonateBombs` worklist, removal-before-blast so nothing double-fires) and broadcasting `SBlast`. The `bombs` map is transient/never-persisted like `burning`. **PvP elimination (Increment 2):** a blast tile KOs any live player standing on it (`koPlayer` → dead + `respawnTicks`≈60 countdown, `SKO`); the killer's `kills` byte increments and rides `SPlayer` (self-kills credit nobody). Dead players are frozen — `cmdInput`/`cmdPaint`/`cmdBomb`/`cmdUlt`/`cmdJump` are ignored while `!alive` — and respawn at `SpawnCoord` after the countdown (`SRespawn` carries the position because movement is client-authoritative). when a `Store` is configured it loads persisted tiles at startup and persists paint upserts/deletes through a serial async queue; `SavedTile.Color == 0` clears a persisted tile. non-blocking `send` drops oldest frames under backpressure — so the **join handshake (Welcome + the painted world + present-player Enters/player states) is NOT sent via `send`**: `Sim.Join` returns those frames and the connection goroutine writes them reliably before the lossy writer starts, otherwise a painted world larger than the 64-frame buffer evicts the Welcome and the client never learns its id.
- `internal/server/server.go` — http mux: `/healthz` JSON liveness encoded from a typed response (`{"status":"ok"}`), `/version` build metadata JSON (`commit_sha`, `build_timestamp`), `/ws` upgrade, and `/` static files (`web/`, only when that dir exists — skipped in the Railway image). WS origin policy comes from `ALLOWED_ORIGINS` (allow-all when unset). one reader loop + one writer goroutine per connection; first frame must be Hello, optionally carrying the role byte. after Hello it writes the join handshake frames returned by `Sim.JoinWithRole` directly to the socket (reliable, may block this one connection) and only then starts the lossy writer goroutine that drains the `out` channel.

## sharp edges
- movement is **client-authoritative** (server only clamps to bounds). no anti-cheat yet — by design.
- `Space` requests paint for the acting player's current rendered 128×128 floor tile, selected by nearest rendered tile center so the colored diamond appears under the player's feet in the isometric view; the most recent paint for a tile wins until overwritten or cleared by ash expiry. painted tiles persist to `public.painted_tile` (keyed on the tile center) when `DATABASE_URL` is set, and are replayed into the painted map on startup, so the painted world survives restarts; color-0 `SavePaint` deletes a persisted tile. with no `Store` (local dev/tests) tiles remain in-memory only and reset on process exit. restored tiles carry ownerID 0 (no live owner — runtime ids don't survive a restart).
- roles and characters are fixed for the connected session. The client persists the character choice locally and sends it in `CHello`; the server validates it against the shipped cast (`horse-poison`, `pigeon-poison`, `pinniped-poison`, `jesus-poison`; legacy `*-pro` ids remain accepted) and includes it in `SEnter`/`SPlayer` presence frames, but does not store it in the position/tile persistence layer. normal paint that changes a tile charges the player's single ult toward 12; ult-painted tiles never charge ults. `Pulse` paints a 3×3 tile square, `Cross` paints center plus two tiles in each cardinal direction, and `Trail` auto-paints the next 8 distinct entered tiles from server-side movement.
- WS origins are allow-all only when `ALLOWED_ORIGINS` is unset (local dev). In production set it to the Vercel client host(s); see `docs/deploy.md`. The engine is a single stateful process — do **not** run multiple replicas (in-memory world would desync).
- Railway Docker builds stamp `/version.commit_sha` from `RAILWAY_GIT_COMMIT_SHA` and `/version.build_timestamp` from the build stage clock via `go build -ldflags`; local `go run` still serves `/version` using Go VCS metadata when available.
- positions are int16; world is fixed 8192². changing `WorldSize`/`CellSize` must keep `WorldSize % CellSize == 0`.
