# Первый мобильный срез: план имплементации

2026-09-10. Пользователь разрешил самостоятельную реализацию и проверки.
Implementation record: [source, commands, checks and device-build gates](../project-map/mobile.md).
Основа — [план платформ](evolving-world-cross-platform-plan.md). Объём этого
среза: общий клиент, оболочки Android/iOS, гостевое подключение и возврат
после фона. Аккаунты, автоматическая эволюция и публикация в магазинах сюда
не входят. Принятый минимум защиты общения остаётся отдельной работой до
расширения аудитории; этот срез не объявляет его реализованным.

## Порядок

1. Создать `mobile/` с закреплённым Capacitor и воспроизводимой поставкой
   существующих HTML/CSS/JS/Three.js. Без нового игрового движка и без загрузки
   сайта через `server.url`. Адрес общего сервера задаётся при сборке.
2. Сохранить браузерные cookie и Origin-проверки. Для приложения использовать
   нативный HTTP с cookie и короткоживущий одноразовый допуск к WebSocket,
   полученный только после проверки гостя. Не хранить постоянный секрет в
   localStorage и не передавать его в URL.
3. Подключить общий клиент через небольшой адаптер транспорта. В фоне
   остановить игру/опрос, при возврате восстановить соединение. Сохранять
   прежние имя, рецепт облика, черновик и ключ повторной отправки.
4. Добавить исходные проекты обеих ОС и инструкции сборки. Проверить
   ограничения Android и iOS до объявления готовых установочных файлов.
5. Проверить авторизацию, срок и одноразовость допуска, отсутствие регрессии
   веба, общий мир/чат, повторы и переподключение. Использовать только
   локальную проверочную базу; остановить временные процессы после тестов.

## Условия и ограничения среды

На этом Linux VDS обнаружена Java 21, но Android SDK и Xcode не обнаружены.
Свободно около 600 МБ на момент начала работы. Не устанавливать большой SDK
до наличия места и не удалять чужие файлы. Проверка исходников/подготовки
пакета не равна сборке APK/IPA или проверке телефона. Для iOS нужна отдельная
macOS-среда; подпись, аккаунты и реальные устройства пока не подтверждены.

## Проверка готовности

Точный результат и незавершённые пункты фиксировать в карте реализации.
Сначала завершить доступные проверки кода и упаковки; сборки устройств,
фоновую cookie-персистентность и трёхстороннюю пробу на телефонах принимать
только после фактического выполнения. Не отправлять приложения в магазины
и не заявлять об их готовности при отсутствии этих результатов.
